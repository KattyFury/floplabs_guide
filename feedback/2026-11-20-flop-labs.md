## Issue body (as posted after edit)

> **Edit 2026-11-20:** removed two claims I had not verified (a 429 we saw on devnet; our agents failing the self-test for a week: our agent has only run against mocks, because our devnet wallets hit `allowance expired` / `wallet_enrollment_cap_reached`). Added CLI 0.7.1 evidence. New hands-on findings are in the first comment.

### Context and disclosure

I maintain a community guide plus a one-command installer that sets up a FLOP-only agent for non-technical users
(https://kattyfury.github.io/floplabs_guide/, source https://github.com/KattyFury/floplabs_guide). It uses the official
`@flop-labs/cli` 0.5.0 for the wallet and gateway key and posts work to Kibble. I am exposed to the incentives below: I
want the agent airdrop and this feedback is eligible for the feedback reward. Everything here comes from building that
guide on devnet between 2026-11-13 and 2026-11-20.

Four points, each with what we saw, the unintended consequence, and a concrete ask. Points 2–4 are policy, point 1 is
the catalog policy behind them.

---

### 1. Agents are scored, but there is no model an agent can actually use

**Seen.** `GET https://api.flop.network/v1/models` on 2026-11-20 lists one model, `qwen/qwen2.5-0.5b-instruct`, with
`supported_parameters: ["max_tokens"]` and `capacity_tpm: 8736` in one datacenter (JP). No `tools`, `tool_choice`,
`response_format`, `stop` or `temperature`. Flop's own launcher agrees: CLI 0.7.1 `flop launch claude|codex` checks the
catalog and refuses any model without `tools` ("does not support tool calls, which claude needs on every turn"), so
it cannot run against the only model served today. Our agent has the same kind of gate (a tool-use self-test before it
may post), so it can be installed but cannot do agent work on devnet.

**Unintended consequence.** The airdrop scores agents on settled compute spend, and the only thing a 0.5B model with no
tool calling can do reliably is spend. So the "agents" that will be ready on testnet day are the ones that skipped the
part that needed a capable model: loops that call the gateway to settle sessions. Builders who tried to make real agents
had nothing to test against and arrive late. Every framework also has to invent its own JSON-in-text parsing, because
`tools` and `stop` are not passed through, which makes agents fragile in different ways that Flop cannot support.

**Ask.**
- Publish the testnet day-1 model catalog now, with each model's `supported_parameters`.
- Launch testnet with at least one model that passes basic tool use (around 8B or larger) and pass `tools`, `tool_choice`,
  `response_format`, `stop` and `temperature` through the gateway.
- Until then, say clearly in the docs that devnet cannot be used to test an agent's behaviour, only its payment path.

### 2. Scoring on raw spend rewards wasted tokens, even with no self-dealing

#405 covers one operator on both sides of a channel. This is the honest-agent case.

**Seen.** For a fixed task, spend is proportional to tokens. Our agent caps itself at 8 steps and 1.5M tokens a day and
trims context to stay cheap. Under the published rule (settled spend), score grows linearly with tokens, so the same agent with a padded
system prompt, no trimming and retries on every answer scores higher for the same work.

**Unintended consequence.** Builders optimise for token burn: long prompts, no caching, retries, re-reading the same
pages. With capacity this small (8,736 tokens/min for the only model) a few padded agents can fill the pool. Real demand gets crowded out by score demand, and miners see load that won't exist after the
snapshot.

**Ask.** Before testnet, publish the scoring formula and make it concave per agent: e.g. square root of daily spend, or a
daily cap, plus credit for active days and distinct sessions. Users who run small, efficient agents every day should not
lose to one burst of padded spend.

### 3. The agent airdrop pushes beginners into hot wallet keys and third-party installers

**Seen.** The official path is a CLI that needs Node 22+ and a terminal. Non-technical users won't do that, so they
copy-paste community one-liners (`irm … | iex`, `curl … | bash`), ours included. Those scripts create the wallet, and the
signing key ends up in plain text in `~/.flop` on the same always-on machine as the agent. The gateway key expires in about
24 h and renewing it needs a wallet signature, so the wallet key has to stay hot next to the agent.

**Unintended consequence.** In testnet week the main scam won't be fake tokens. It will be fake installers: "one command
to farm the FLOP agent airdrop". Users have been trained to run them, and each one can read a wallet key. A single
popular malicious script empties many wallets, and Flop gets the blame.

**Ask.**
- Make a spend-capped credential the default for agents. The pieces exist: `flop session create --daily-cap --tx-limit
  --ttl` and `flop proxy --session-owner`. But `agent credential` (the documented agent path) is wallet-signed, and the
  agent onboarding and integration pages don't mention session keys. See the comment below for details.
- A page on flop.finance/official on how to check a community tool (read the script, what it should never ask for,
  official CLI package name and checksum), plus a clear statement that Flop endorses no installer, or a list of reviewed
  ones.
- An official minimal agent template, so the default copy-paste source is Flop's own repo.

### 4. Rewarding feedback with mainnet tokens is filling the tracker with duplicates

**Seen.** This repo has had 124 issues opened since 2026-11-15, and 74 since 2026-11-18. A search for "allowance expired"
returns 22 issues and "enrollment" returns 30, mostly the same problem as #6 (26 comments).
Real breakage like #377 (miner fences its signer permanently) sits in the same list as rewrites of known issues.

**Unintended consequence.** The reward goes to whoever posts, so people post. Maintainer time in the last four days before
testnet goes to triage instead of fixes, and real bugs from quieter operators get buried. This issue is part of the
problem I'm describing, so I've kept everything into one issue and linked the existing ones instead of refiling them.

**Ask.**
- Reward issues that are accepted (labelled confirmed, or fixed), not issues opened.
- Pin one tracking issue per known problem (enrollment/allowance first) and ask for data there, closing new duplicates
  with a link.
- Move policy debate to GitHub Discussions, and add an issue template with a "searched for duplicates" checkbox.
- Publish how feedback rewards are judged, so people write less and better.

Happy to test any of the above on testnet day with the guide's users and report back in one place.

## Follow-up comment (CLI 0.7.1 hands-on)

Hands-on follow-up. I checked `@flop-labs/cli@0.7.1` (npm, published 2026-11-20 05:41 UTC) using only commands that refuse before touching a wallet. Each item has the exact output or code location so it can be checked quickly.

### A. The current CLI has no testnet path for agents (4 days before testnet)

```
$ flop --offline --network testnet agent credential --json
{ "ok": false, "code": "COMMAND_FAILED", "message": "agent credential requires --network devnet", "retryable": false }

$ flop --offline --network testnet agent launch claude
Error: flop launch claude runs on the public devnet only; drop --network testnet or pass --network devnet
```

Credential paths are also hard-coded to devnet (`~/.flop/devnet-agent-key.json`, `devnet-wallet-agent-key.json`, `devnet-enroll-wallet.json`). `flop network status --network testnet` returns `profile_status: planned`, and `wss://testnet.flop.network` and `faucet.testnet.flop.network` can't be reached yet. That part is expected before launch.

**Why it matters:** every agent guide and framework that wraps the CLI (ours included) can't prepare or test a testnet path. Everyone will upgrade and retry on day 1 at the same time, which is the same burst pattern that already overloads devnet enrollment (#6, #399).

**Ask:** ship the testnet agent path in a CLI release now, behind a flag if needed, or publish exactly which command agents will run on day 1, so integrators can wire it up before launch.

### B. `agent credential` keeps a plaintext wallet mnemonic on the agent machine

When there is no wallet, `agent credential` generates one and saves `{ type, address, mnemonic }` as plain JSON to `~/.flop/devnet-enroll-wallet.json` (`enrollmentWallet()` → `saveCredential`). The `0700` directory check (`ownerOnly`) returns `true` on `win32` without checking anything. Meanwhile the CLI already supports `--keystore` + `--password-env` (encrypted Polkadot JSON) for other commands, plus bounded session keys (`flop session create --daily-cap 50 --tx-limit 5 --ttl 86400`, `flop proxy --session-owner`).

**Why it matters:** the agent path, which the airdrop sends beginners down, is the one that leaves a full wallet mnemonic on an always-on box. The safer pieces exist but aren't the default, and the spend-control docs page is still marked "Draft whitepaper".

**Ask:**
1. `agent credential` writes an encrypted keystore (or uses the OS keychain) instead of a plaintext mnemonic.
2. The documented agent setup uses a session key with a daily cap, so the agent machine never holds the owner key.
3. Add one line to the agent onboarding FAQ explaining which file holds the owner key and how to move it off the agent machine.

### C. Docs and package pins drift during the release burst

`docs/sdk-references` (updated 2026-11-20) tells users to run `npx --yes --package @flop-labs/cli@0.7.0`, but 0.7.1 shipped an hour later. That makes three CLI releases in two days (0.6.0, 0.7.0, 0.7.1). Integrators pin versions (we pinned 0.5.0), and there is no statement of which versions still work with the gateway and runtime (related: #411).

**Ask:** a short compatibility line on the SDK page ("minimum CLI for devnet/testnet agents: x.y.z"), updated with each release.
